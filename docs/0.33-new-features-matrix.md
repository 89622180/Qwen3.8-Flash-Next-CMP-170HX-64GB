# 第五轮：vLLM 0.33 新增功能逐项实测（2026-11-04，CT103）

方法：先用两版 `vllm serve --help=all` 的 flag 全集 diff 列出真正的新增面（不是看 release note，
也不只看 dataclass 字段），再用 `QWEN_PRINT_COMMAND=1` 筛过 argparse，最后每个候选占一次真启动。
所有臂在同一引擎、同一脚本、同一配对 seed 上跑：

- prefill：`bench_conc_text.py 1 <PTOK> 32 <seed>`，取 TTFT 推出的 tok/s，三格 = ~1289 / ~2575 / ~9880 token；
- decode：`benchmarks/decode_long_sample.sh`（6 个配对 seed × 1024 输出，mean/median）；
- 每臂都记录 KV 池行与 `preempt`，`MainPID == :8000 owner` 作为身份门。

## 2. FLy 交错复测：+9% 是真的，但手段是有损的

第一遍量出 fly 170.1/152.2 vs base 158.5/138.9（+10%），但我不接受这个对比：
**同一份标准配置**在本会话内三次分别给出 median 138.9 / 140.1 / 153.5，散布就有 ±6%，
而两臂相隔 30–45 分钟。于是做 A-B-A-B-A-B 交错三对（每臂一次真启动，只跑 decode）：

| 对 | fly median | 标准 median | Δ |
|---|---:|---:|---:|
| 1 | 151.4 | 139.2 | **+8.8 %** |
| 2 | 156.3 | 140.9 | **+10.9 %** |
| 3 | 152.8 | 215.2（6 个 seed 里 3 个进了循环） | 不可用，见 §3 |

把第 3 对里“进循环”的 run 剔掉（acc_len ≥ 4.9 的行），标准侧非循环中位 = 141.1 → **+8.3 %**。
三对都是正的且量级一致：**fly ≈ +9 % 单流解码，prefill 与 KV 池零代价**
（`GPU KV cache size 553,415 tokens / 2.11×` 三臂全同，`preempt=0`）。

代价是说出来的：引擎自己打 `FLy verification is a lossy speculative decoding method and may
degrade model outputs`，它的机制就是接受标准拒绝采样本会丢掉草案 token（acc_len 分布整体上移）。
10 题事实探针（temp 0、48 token、`benchmarks/qa_lossy_check.sh`）：两臂同为 **8/10**，
但 10 答里只有 2 答逐字节相同（其中一题 fly 反而更早给出答案：“水的化学式是 H₂O”，
被我的 ASCII 匹配判成 MISS）——所以“分数没降”不等于“输出没变”。

**因此本轮不默认开启 fly。** 要开就一个 drop-in（`configs/ct103-0.33-dflash2-fly.conf`），
一条 `Environment=QWEN_REJECTION_METHOD=fly` + `Environment=QWEN_FLY_WINDOW=2`；
`serve.sh` 已经接好这两个开关（连同 `QWEN_LOOKAHEAD_OFF`）——之所以走 env 而不直接传 JSON，
是因为 systemd 的 `Environment=` 对带空格/引号的值是个坑（见第四节）。

## 3. 这个 harness 本身在骗人（重要）

把每个 seed 的单跑值排开就看见 decode tok/s 是**双峰**的：

- acc_len 4.93–4.97（4 个草案 token 几乎全中）→ 240–268 tok/s；
- acc_len 2.45–3.20 → 126–180 tok/s。

落在哪个峰取决于贪心生成有没有锁进重复循环（提示词是同一句话循环 12 遍 + `ignore_eos`），
**与配置无关**：同一份标准配置能在一次跑里 6 个 seed 中 3 个进循环（AB3_std mean 205.1），
下一次一个都不进（AB1_std mean 145.7）。这解释了本会话里所有“同配置同 seed 给出 161.6 和
262.8”的怪事，也意味着：**在这个 harness 上，<20 % 的差根本判不出来**——包括我前面几个臂的
“+3% / −5%”。要拿可靠数字得换非重复的自然提示词，或者按 acc_len 分层统计（只拿非循环 run 求中位），
别加样本量了事。

## 4. 工具链坑（本轮实际踩到）

- systemd：`Environment=QWEN_EXTRA_ARGS=--moe-backend triton` 会被判为非法赋值而丢掉后半段，
  argparse 接着报 `expected one argument`；必须写成 `Environment=QWEN_EXTRA_ARGS="--moe-backend triton"`。
- 本轮新增一个失败臂的原因就是忘了引号，不是引擎拒绝。
- `QWEN_EXTRA_ARGS` 用 `read -r -a` 拆，只能传“不带值内空格”的普通 flag，JSON 值的 flag 请走专名 env。
- 三臂矩阵里每个“起不来”的臂都只花了 12 s（验证层就拒），不占卡——这类开关先用
  `QWEN_PRINT_COMMAND=1` + 真启动看报错，比读文档快得多。
