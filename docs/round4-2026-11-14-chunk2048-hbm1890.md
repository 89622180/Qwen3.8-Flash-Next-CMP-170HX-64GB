# 第四轮（2026-11-14）：chunk 8192→2048 复测、300 W 对齐、HBM 1890 MHz 单卡实测

## 0. 结论

| 改动 | 结果 | 处置 |
|---|---|---|
| `QWEN_BATCH_TOKENS` 8192 → 2048 | 8k prefill **−35 %**、32k −14 %、131k −3.6 %；同一 KV 预算下 KV 池 **+10.5 %**；decode 噪声内不变 | **采用**（`configs/zz-chunk2048.conf`） |
| HBM `RmHbmPllNdiv` 64 → 70（只给 `07:00.0`，1728 → 1890 MHz） | 暖机后 8k 2.78–2.80 s，与默认档一致；32k/128k 差异方向互相打架 | **不采用**，保持默认 |

## 1. 口径

同卡、同模型（`Qwen3.8-Flash-Next-Uncensored-AutoRound-3bpw-MTP` + DFlash2
`incoai-...-DFlash2-W8A16G128-GPTQ` 草稿）、同固定脚本：单流 1 token 取 TTFT；
decode 用 512 提示 / 256 输出、`temperature=0`、`ignore_eos=true`。

- serving GPU = `07:00.0`（`nvidia-smi` index 1），实验期间限 **300 W**（= `power.max_limit`）
- KV 预算 `--kv-cache-memory-bytes 11542724608`（10.75 GiB）
- capture list 不含 2048 桶（`[1..32,64,128,256,512,1024]`），即第 10 节口径
- `QWEN_SEQS=8`、`QWEN_MTP=5`、`QWEN_KV_DTYPE=fp8_e5m2`、`VLLM_SW_BLOCK_SIZE=1072`

## 2. chunk 8192 → 2048（同一次开机内单变量）

| pin | 8192 | 2048 | 变化 |
|---:|---:|---:|---:|
| 512 | 0.338 s | 0.248 s | −27 % |
| 2,048 | 0.907 s | 0.802 / 0.815 s | −11 % |
| 8,192 | 3.93 / 4.04 / 4.05 / 4.06 s | **2.608 / 2.617 / 2.636 s** | **−35 %** |
| 32,768 | 11.10 s | 9.530 / 9.587 s | −14 % |
| 131,072 | 40.151 s | 38.699 s | −3.6 % |

- KV 池 **570,059 → 630,065 tok**（2.17× → 2.40× @ 262k）；`QWEN_KV_BYTES` 没动，
  涨的是块对齐（chunk 决定每块 token 数，`max_concurrency` 跟着变）
- decode 512/256：C1 177.0 / 194.4、C4 448.8 / 461.3、C8 625.2 / 679.0 tok/s；
  8192 臂是 C1 174–183、C8 603–666——**在 run-to-run 噪声带内**
- 引擎身份每个臂都用 `systemctl show MainPID` 与 `ss -lptnH sport=:8000` 的 owner pid 对齐过

**8k 那个台阶不是 capture 桶的问题**。第 10 节已经把 capture 列表裁到 `[1..1024]`，
1298 tok 和 2592 tok 都不再白算 slot；这里的 4 s 是 chunk 边界本身：8192 恰好一整块，
一次 forward 吃满；同样的 8192 token 切成 4×2048 只要 2.6 s。机制尚未归因（PLE AIO
的 demand/prefetch 交错、以及 attention 分块长度都在嫌疑名单里），但两次同日测试
（17:59 与 18:19）都复现，且 2k / 32k 同向受益，不是噪声。

## 3. HBM NDIV=70 / 1890 MHz（只给 07:00.0）

```ini
# /etc/modprobe.d/90-cmp-vbios-override.conf
options nvidia NVreg_RegistryDwordsPerDevice="pci=0000:01:00.0;RmLinuxVbiosOverride=2;RmLinuxVbiosOverrideSize=393216;RmHbmPllNdiv=64;pci=0000:07:00.0;RmHbmPllNdiv=70"
options nvidia NVreg_RegistryBinaryFilePerDevice="pci=0000:01:00.0;RmLinuxVbiosOverrideImage=615.71.09/vbios-override/vbios.bin"
```

生效证据（整机重启后）：

```
dmesg | grep HBMPLL_OC
  NVRM: GPU1 _kgspBootGspRm: HBMPLL_OC: done, 8 FBPAs at NDIV=70 (1890 MHz)
  NVRM: GPU1 kgspInitRm_IMPL: HBMPLL_OC: post-GSP POST: COEFF=0x00014601(NDIV=70) ... lock=1 iter=0

nvidia-smi --query-gpu=index,pci.bus_id,clocks.mem --format=csv,noheader
  0, 00000000:01:00.0, 1728 MHz      # 默认卡不受影响
  1, 00000000:07:00.0, 1890 MHz
```

两个坑：

1. **内核日志的 `GPU0/GPU1` 编号与 `nvidia-smi` 索引相反**——本次 `dmesg` 里的 `GPU0`
   才是 `07:00.0`（VBIOS `92.00.6D.00.0A`），`GPU1` 是 `01:00.0`。核对一律按 PCI 地址，
   不要按 `GPU n`。
2. **`modprobe -r nvidia` 不可用**：`dsh-console.service`（PVE 上的 vLLM 控制台）持有
   `/dev/nvidia*`，卸载返回 rc=1，`modprobe` 重新加载后仍是旧档位。所以换 HBM 档位
   只能整机重启。`coolercontrold` 也要先停。

结果（B/C 两臂各在开机后 ~6 min 测一轮、~10 min 再复测一轮）：

| pin | 1728 MHz（C 臂） | 1890 MHz（B 臂） |
|---:|---:|---:|
| 8,192 | 2.96 / 2.96 / 3.02 / 3.05 s；暖机 2.75 / 2.78 / 2.84 / 2.89 s | 3.09 / 3.17 / 3.24 s；暖机 2.78 / 2.78 / 2.80 s |
| 16,384 | 6.92 s；暖机 5.18 s | 5.61 s |
| 32,768 | 10.73 / 10.85 s；暖机 10.23 / 11.52 s | 10.36 / 11.58 s；暖机 10.26 s |
| 131,072 | 43.98 s | 41.43 s |
| decode C8 聚合 | 630.1 / 638.6 tok/s | 629.1 / 652.5 tok/s |
| decode C4 聚合 | 430.9 / 442.7 | 402.6 / 453.6 |
| decode C1 | 183.2 / 279.8（离群） | 187.8 / 174.7 |

**没有收益。** 暖机后 8k 两边都是 2.78–2.80 s；32k/128k 的差异方向互相打架（128k 1890 快
6 %，32k 1890 慢 1–7 %），而同臂 run-to-run 本身有 5–14 %，跨整机重启还有 ~5 % 的系统
偏移（A 臂同一份配置 8k 2.61–2.64 s，C 臂 2.75–2.89 s）。11-09 的纯带宽微测是
1728 → 1598 GB/s、1890 → 1773 GB/s（+11 %），但这条管线里 prefill 的瓶颈在 PLE SSD
路径（持续读 45–65k IOPS / 200–300 MB/s）与 SM 侧计算，HBM 带宽兑换不出来。

两侧都是 300 W、SM 1455 MHz、HBM 温度 66–67 °C、throttle 标志 0（仅采样到一次 `0x4`），
所以不是功耗/温度/节流假象。

## 4. 300 W 对齐

`07:00.0` 从 180 W 提到 300 W 后重测，与第 4 节「250 → 300 W 吞吐变化为零」一致：
本负载在 180–300 W 区间不撞功耗墙（采样峰值 303–332 W 属瞬时尖峰，SM 稳定 1455 MHz）。
功率上限是机主策略项，实验结束已回到 180 W。

## 5. 最终状态

- `QWEN_BATCH_TOKENS=2048`（`configs/zz-chunk2048.conf`）
- `QWEN_KV_BYTES=11542724608` → 630,065 tok
- HBM 保持 NDIV=64 / 1728 MHz；`90-cmp-vbios-override.conf` 已回到单卡覆盖的原样
- 功耗上限回 180 W；PVE 测试结束后关机
